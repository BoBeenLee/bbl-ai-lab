# Log

## 2026-09-09

- `cad` 가 두 번째 설계를 냈다. `designs/2026-09-09-phone-cradle` — **대상 기기를 고정하지
  않는 첫 설계**다. 맥북 받침대는 `Mac15,7` 하나에 맞춘 치수가 상수였는데, 여기서는 폰 기종을
  안 정하고 "모든 폭을 커버" 를 요구로 받았다. 그래서 **치수 의존을 파라미터 범위가 아니라
  형상으로 없애는** 문제가 됐고, 그 과정에서 이 hub 가 이미 적어 둔 규율("제약을 크기로 쓰기
  전에 그 크기가 어디를 기준으로 한 것인지 먼저 적을 것", 2026-09-06)이 처음으로 설계 자체에
  적용됐다.

- **접촉이 점이냐 면이냐가 치수 의존을 가른다. 그리고 면 접촉은 저절로 생기지 않는다.**
  처음 세운 근거가 틀렸다 — "폰이 립에 앉고 등판에 기대므로 각도는 등판이 정한다" 는 홈 바닥이
  수평이면 성립하지 않는다. 정역학을 풀면 x 방향 균형이 `-N_back·cos(θ) = 0` 이라
  **폰이 등판을 아예 안 누른다.** 앞으로 밀려 립에 앉고, 접촉이 립 안쪽면과 등판 윗모서리
  **두 점**이 되어 각도가 두께에 종속된다. 고치는 값은 하나였다 — 홈 바닥을 등판각만큼 뒤로
  기울여 등판에 수직으로 두면 밑면·뒷면이 둘 다 면으로 닿고 두께가 식에서 사라진다.
  **"모든 X 를 커버" 요구가 오면 범위를 넓히기 전에 X 가 왜 식에 들어오는지를 먼저 푼다.**

- **그 한 값이 미검증 항목 하나를 통째로 없앴다.** 디딤면이 등판에 수직이면 마찰 0 에서도
  평형이 있다. 맥북 받침대의 가장 큰 열린 항목(C-005 "마찰이 실제로 버티는가", 강철 상대
  실측값을 알루미늄에 쓰는 것이 근거였다)이 이 설계에는 **존재하지 않는다.** 근거가 부족할 때
  근거를 더 찾는 것 말고 **그 근거가 필요 없는 형상으로 가는** 길이 있다. 다른 repo 에도
  옮겨 간다 — 검증 못 하는 가정이 설계를 지배하면 가정을 검증하기 전에 가정을 지울 수 있는지 본다.

- **못 고치는 한계가 다른 항의 설계 목표를 정해 줬다.** 이 받침은 1N 안팎에서 책상 위를
  밀려나고, 그걸 고치려면 마찰 0.4 이상이 필요한데 실측 범위 밖이고 고무 패드는 2재질이라
  사용자 제약이 막는다. **부품 하나로는 해가 없다.** 그래서 밑면 길이 목표를 "몇 N 을 버틴다"
  가 아니라 `F_tip >= F_slide` 로 잡았다 — 넘어지기 전에 미끄러지게. 밀려나는 것은 되돌릴 수
  있고 넘어지는 것은 아니다. 근거 없는 목표값(예: 2N)을 못박고 거기 맞추면 밑면만 길어진다.

- **"컴팩트하게" 의 지배 변수를 두 번 잘못 짚었다.** 처음엔 각도라고 했고, 다음엔 계단이라고
  했는데 둘 다 아니었다. 각도는 누름 전도 모멘트에 5% 밖에 기여하지 않고(지배하는 항은 누르는
  높이 `ℓ·cos²θ` 다), 계단은 디딤면 깊이만큼 하중점을 뒤로 민다(1각 120 / 2단 145 / 3단 170mm).
  **어림으로 "이게 지배할 것" 이라고 쓰기 전에 식의 항을 세어 본다.** 두 번 다 계산이
  직관을 뒤집었다 — 가로가 세로보다 3배 안전하고, 무거운 폰이 가벼운 폰보다 안전하다.

- **그리고 그 계산을 근거로 "조절 폭과 컴팩트함은 구조적으로 충돌한다" 고 쓸 뻔했는데, 그건
  한 칸 과했다.** 계단이 밑면을 먹는다는 계산은 맞다. 틀린 것은 **채널이 같은 쪽을 봐야 한다는
  적지도 않은 가정**이었다. 반대를 보게 하면 전도축도 같이 뒤집혀 두 좌석이 밑면을 나눠 쓰지
  않고 각자 전체를 지레팔로 쓴다 — 두 번째 각도가 밑면을 1mm 도 안 늘렸다 (`cad` D-007).
  **"X 와 Y 는 충돌한다" 는 결론은 그 계산이 깔고 있는 배치 가정까지 적어야 쓸 수 있다.**
  D-009(조절 폭 ↔ 안정성)는 진짜 충돌이었지만 이건 아니었고, 둘을 같은 모양으로 본 것이
  이번의 오류다. 방사 배치까지 밀면 좌석 N 개가 전부 같은 지레팔을 쓰는데, 거기서는 값이
  길이가 아니라 **부피**로 청구된다 (8각 176cm³ vs 양단 120cm³) — 충돌이 사라지는 게 아니라
  **다른 축으로 옮겨 간다.**

- **레퍼런스에서 값이 아니라 실패 원인을 가져왔다.** print-in-place 힌지는 무단 각도 조절을
  주지만 유격이 0.2~0.3mm 이고 최대 실패 유형이 융착인데, 그 원인이 과압출과 첫 층 눌림 —
  **둘 다 프린터 캘리브레이션**이다. `cad` 는 프린터가 없고 출력 대행이라 그걸 통제하지 못한다.
  어떤 공개 모델은 특정 슬라이서 옵션을 켜야 한다고 명시하는데 업체에 요구할 수 없는 조건이다.
  **"이 값이면 된다" 가 아니라 "이 값을 누가 보장하나" 로 읽으면 선택지가 갈린다.**
  그리고 선행 출원(US 2016/0286953 A1)은 등록되지 않았고, 그쪽 채널은 바닥이 평평해서
  두께가 각도를 바꾼다 — 레퍼런스가 이미 푼 문제와 안 푼 문제를 갈라 봐야 뭘 가져올지 정해진다.

- **대상이 집합이면 검사가 꼭짓점을 순회해야 한다.** 기기 하나짜리 설계에서 이식한 `check()`
  를 그대로 쓰면 대표값 하나만 보고 통과한다. `cradle.py` 는 폰 envelope(두께·길이·질량·자세)
  의 꼭짓점을 돌고 실패 메시지마다 어느 꼭짓점인지를 적는다. `steps.py` 에서 가져온 것은
  수식이 아니라 **규율**이다 — 조건마다 그것을 깨는 입력을 하나씩 넣는 selfcheck.

- 설계가 둘이 되면서 `design.py` 의 단일 설계 가정이 드러났다. `--design` 없이 exit 2 이고,
  `iterdir()` 에 필터가 없어 `.git` 까지 후보로 센다. **`check` 는 발주 전 게이트인데 기본이
  exit 2 인 게이트는 건너뛰게 된다.** 공유 도구라 이번엔 코드를 안 고치고 README 만 고쳤고,
  고치는 방식을 결정 항목으로 열었다.

## 2026-09-06

- `projects/voice-agent` private repo 추가. 여덟 번째 project repo다. 음성 에이전트 지식
  (축적층 `knowledge/`)과 에이전트 한 건(산출층 `agents/<날짜>-<slug>/`)을 디렉터리로 가르는
  규율만 세우고 에이전트는 아직 없다. private 인 이유는 `hiking`·`cad` 와 같은 축이다 —
  통화 녹음·전사·목소리가 쌓이면 개인 데이터가 된다. 매니페스트 등록은 `bash ops/repo-sync.sh`
  자동 등록으로 했다.

- **이식에서 처음으로 대상이 갈렸다.** `travel` → `hiking` → `cad` 는 조사 프로토콜과 스크립트를
  통째로 가져갔지만 `voice-agent` 는 `check_links.py` 와 값/지식 분리 규율만 가져가고
  `survey.py`(영상 전수조사, 424줄)를 **두고 왔다.** 앞의 셋은 공식 문서가 얇고 실전 지식이
  영상에 있는 도메인이었는데, 음성 에이전트는 1차 출처가 요금·약관 페이지고 그 둘은 fetch 가
  되고 날짜가 찍힌다. 이식이 "무엇을 가져올까" 가 아니라 **"무엇을 두고 올까"** 를 정하는 일이
  된 첫 사례다. 안 쓸 스크립트를 가져오면 `cad` D-003 이 거부한 빈 인프라가 남는다.

- 값/지식 분리 규율이 이 도메인에서 한 칸 넓어졌다. `cad` 는 **가격**을 1등급(아무 파일에도 안 씀)에
  두었는데, `voice-agent` 는 거기에 **무료 티어 한도 숫자와 모델 ID** 를 넣었다 (D-002). 무료 티어는
  프로바이더가 사용자를 잡으려고 여는 자리라 가격보다 빨리 바뀌고 — 조사 당일에도 Gemini 는
  같은 Live API 안에서 모델마다 무료 티어 유무가 갈렸다 — 모델 ID 는 세대가 바뀌면 조용히 404 가
  된다. 대신 **한도의 축**(세션 분·동시 세션·배포 수·WebRTC 분·전화번호)은 숫자가 바뀌어도
  유지되므로 그것만 `knowledge/` 에 쓴다. 축이 지식이고 숫자가 값이다.

- 이 도메인의 게이트는 **두 층에 따로 걸고 곱으로 판정한다** — 프레임워크가 오픈소스여도 실행이
  무료가 아니고, 모델에 무료 티어가 있어도 프레임워크가 매니지드 유료면 0원이 아니다. "무료
  voice agent 제품" 에 답이 없는 이유가 이것이다. 완성형 제품은 두 층을 묶어 팔기 때문에 무료
  자리가 없다. 2026-09-05 게이트 결과 LiveKit Agents + Gemini Live 계열이 유일한 통과 조합이었다.

- **후보 확정과 채택을 갈랐다** (D-004). `cad` 의 D-004 는 FreeCAD 를 릴리스 노트로 검증해
  확정했지만, 여기서는 게이트만 통과시키고 채택은 미뤘다. 지연과 한국어 품질은 문서로 확정할 수
  없기 때문이다 — 벤더 발표 지연은 실측이 아니고 영어 벤치마크는 한국어에 이전되지 않는다.
  근거 없는 확정이 근거 있는 미확정보다 나쁘다.

- `knowledge/data-policy.md` 는 프로바이더 네 줄 중 **한 줄만 채워져 있고, 그 빈 칸이 문서의
  내용이다.** 이 도메인에서 되돌릴 수 없는 비용은 요금이 아니라 흘려보낸 음성이다. Gemini 무료
  티어는 입출력을 학습에 쓰고 사람이 읽는다(약관 확인). 그래서 "무료와 기밀은 같이 갈 수 없다" 가
  신중함이 아니라 게이트의 논리적 귀결이 된다.

- **`cad` 가 첫 산출물을 냈다.** `designs/2026-09-05-macbook-stand` — MacBook Pro 16인치용
  경사 받침이고, 코드가 원본이라 `.FCStd` 를 커밋하지 않는다 (`src/build.py` 가 STEP·STL·3MF·
  측면도를 낸다). hub 에서 **산출물이 문서가 아니라 물건인 첫 repo** 다. "AI 가 낸 치수는 실행해
  확인하기 전까지 추정" 이라는 규칙이 여기서 기계적 절차가 됐다 — 내보낸 STL 을 **다시 읽어**
  솔리드와 경계 상자를 대조한다. 모델이 맞는지가 아니라 내보내기가 맞는지를 보는 검사이고,
  단위·스케일 사고는 여기서만 잡힌다.

- **규율이 실패를 지우지 않고 기록으로 남겼다.** 세 번째 형상(육각 단면을 굴려 3단)은 서지
  못하는 물건이었다. 사용자가 "약간의 압력에도 2, 3단은 쓰러질 것 같다" 고 지적했고, 다시
  계산해 보니 압력 없이도 세 단 전부 하중점이 밑면 밖이었다. 이때 `design.yaml` 의
  `reconciliation` 에 **`불일치` 판정이 있다는 것이 결정적이었다** — 실패한 설계를 커밋에서
  지우는 대신 "이 형상은 서지 못한다" 를 판정으로 박고 `status: 재설계` 로 두었다.
  실패가 파일 안에 남으니 다음 형상이 같은 조건을 검사 항목으로 물려받았다.

- **크기만 보는 제약은 배치 실패를 못 본다.** 전도 조건을 `밑면 ≥ 2 × 들림 × tan(경사) × 여유`
  로 썼는데, 이 식은 하중이 밑면 한가운데 걸린다고 **가정**한다. 볼록 다각형을 굴리면 바닥에
  닿는 면과 하중이 걸리는 면이 앞뒤로 어긋나고, 조절 폭을 키우려고 길쭉하게 만들수록 그
  어긋남이 커진다. 즉 **조절 폭과 안정성이 정면으로 충돌하는데 길이만 보는 식은 그 충돌을
  구조적으로 볼 수 없다.** 다른 repo 에도 옮겨 가는 교훈이다 — 제약을 크기로 쓰기 전에
  그 크기가 어디를 기준으로 한 것인지 먼저 적을 것.

- **조건 붙은 값이 설계 상한을 정했다.** `cad` 규칙 6("치수는 단위·출처·조건 없이 쓰지 않는다")이
  실제로 값을 깎은 첫 사례다. 3D 프린팅 PLA 의 정지마찰 실측(0.20~0.30)을 찾았는데 조건 넷이
  달려 왔다 — 상대재가 강철이지 알루미늄이 아니고, 시편 면이 갈려 있어 출력 그대로가 아니며,
  하중 범위와 접촉 압력이 우리와 자릿수가 다르다. 그래서 고시가 허용하는 15도(마찰 0.268 요구)를
  포기하고 **12도(0.213)에서 멈췄다.** 조건 없이 "PLA 마찰 0.3" 만 적어 두었다면 15도로 갔을
  것이고, 그건 근거 없는 숫자에 기댄 설계가 된다.

- **규칙 4(단일 출처)가 저장소 바깥으로 나갔다.** `cad` 가 출력 대행에 보낼 견적 요청서를
  `design.yaml` 에서 생성한다 (`src/make_quote.py`). 손으로 옮긴 숫자가 하나도 없으므로
  **업체에 보낸 치수와 저장소의 치수가 어긋날 수 없다.** 설계를 고치고 다시 빌드하면 요청서도
  따라 바뀐다. 지금까지 단일 출처는 repo 안의 문서끼리 안 어긋나게 하는 규율이었는데, 외부로
  나가는 문서를 같은 원본에서 뽑으면 "보낸 것과 가진 것이 다르다" 는 실패 유형 자체가 사라진다.
  다른 repo 에도 그대로 옮겨 간다 — 견적 요청서든 설정 파일이든 보고서든 밖으로 나가는 것은
  원본에서 생성한다.

- **"값이 아니라 링크" 규율이 정작 값이 필요한 순간에 시험됐고, 선이 어디인지 처음 드러났다.**
  발주 직전에 업체 규격을 조회했더니 **최소 벽두께 1.2mm** 가 나왔고 그건 곧바로 설계 게이트였다
  (우리 벽 3mm 가 2.5배 여유로 통과). 가격·납기는 여전히 아무 파일에도 안 썼지만 이 규격은
  `knowledge/print-rules.md` 에 적었다. `cad` 규칙 1 의 1등급(조회 시점 값)과 3등급(안 썩는 것)을
  가르는 선이 **"바뀌면 설계가 틀리는가"** 라는 것이 실무에서 확인된 셈이다. 가격이 바뀌어도
  설계는 맞지만 최소 두께가 바뀌면 설계가 틀린다.
